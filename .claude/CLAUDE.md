Файл `DEVELOPMENT.md` содержит критически важную информацию о структуре проекта и workflow разработки.

1. **Работай ТОЛЬКО в папке `diabolic-dev\`** - это рабочая папка с git репозиторием

4. **Локальные коммиты можно и нужно делать** для сохранения прогресса
5. Перед тестированием в игре используй robocopy из DEVELOPMENT.md

## Git Workflow

⚠️ **ВАЖНО: НИКОГДА не упоминай ИИ в описании коммитов!**
- Автор всегда: Arahort
- Не пиши "AI-generated", "Generated by AI", "Claude" и т.д.
- Пиши коммиты как будто их написал человек-разработчик

### Локальные коммиты (можно делать свободно)
```bash
cd "X:\Games\World of Warcraft\diabolic-dev"
git add .
git commit -m "Описание изменений"
```

### Push на GitHub (ТОЛЬКО по просьбе пользователя!)
```bash
git push origin github
```

### Создание релизов (ТОЛЬКО по просьбе пользователя!)

⚠️ **КРИТИЧЕСКИ ВАЖНО:** Коммит и тег ДОЛЖНЫ быть отправлены ВМЕСТЕ в одном push!

GitHub Actions срабатывает только когда тег и коммит приходят одновременно!

**Правильный порядок:**
```bash
# 1. Обновить версию в DiabolicUI3.toc и CHANGELOG.md
# 2. Создать коммит
git add DiabolicUI3.toc CHANGELOG.md
git commit -m "Update version to X.X.X"

# 3. Создать тег НА ЛОКАЛЬНОМ коммите (который ещё НЕ на GitHub!)
git tag -a release-X.X.X -m "Release X.X.X"

# 4. Отправить коммит И тег ВМЕСТЕ
git push origin github --follow-tags
```

**❌ НЕПРАВИЛЬНО:**
```bash
git push origin github           # коммит отдельно
git push origin release-X.X.X    # тег отдельно - Actions НЕ сработает!
```

**✅ ПРАВИЛЬНО:**
```bash
git push origin github --follow-tags  # коммит И тег вместе - Actions сработает!
```
